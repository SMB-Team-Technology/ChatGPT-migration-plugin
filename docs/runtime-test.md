# Installed ChatGPT Work smoke test

This is a **manual test protocol**, not a record of a completed runtime test. Use only synthetic data until these checks pass. The terminal test suite and `doctor` do not establish plugin discovery, ChatGPT permissions, or production AIWP support.

## Before the test

- Use ChatGPT desktop Work with permitted local execution.
- Register this repository's local marketplace and install the package as described in [README](../README.md).
- Start a new Work chat; installed resources may be cached.
- Keep the output outside repositories in a new temporary directory.
- Do not upload the generated bundle to production AIWP.

## Test prompt

Select the installed migration skill, then give it this request:

> Run a synthetic migration rehearsal using the chatgpt-synthetic.json fixture bundled in your installed plugin. Collect conversations only. Show the coverage report and preserve both branches. Build and validate a new bundle in a temporary directory outside the repository. Do not read my personal exports or other local data, and do not upload anything. Report the installed plugin version, execution environment, output path, and anything this test does not verify.

## Evidence to record

1. The plugin and skill are discoverable in Work, and the skill reads its installed instructions.
2. The helper path resolves from the installed package; it does not rely on the developer's checkout or current directory.
3. Node is at least version 20. The installed helper runs its own `doctor` and reports pilot compatibility accurately.
4. The selected input is `test/fixtures/chatgpt-synthetic.json` within the same installed package. If the host does not mount the fixture or helper, record that failure; do not silently replace it with a script generated by the model.
5. Scan returns the expected synthetic conversations and category limitations without reading unrelated inputs.
6. The produced bundle preserves the fixture's retained message IDs, branch parents, and active message. Compare structurally with the fixture; a success message alone is insufficient.
7. Validation succeeds for the file actually produced, and the file can be opened or downloaded by the user.
8. A second build to the same path refuses to overwrite it.
9. After restarting, repeat from a different working directory. Confirm the tested installed version rather than assuming the current source tree is running.
10. Repeat as an ordinary teammate. External personal-account installation needs its own rehearsal; company workspace availability is not evidence it works for clients.

## Terminal comparison

From the package root:

```sh
npm test
node scripts/aiwp-migrate.mjs doctor
node scripts/aiwp-migrate.mjs scan --export test/fixtures/chatgpt-synthetic.json --categories conversations
migration_test_dir=$(mktemp -d)
node scripts/aiwp-migrate.mjs build --export test/fixtures/chatgpt-synthetic.json --categories conversations --out "$migration_test_dir/bundle.json"
node scripts/aiwp-migrate.mjs validate "$migration_test_dir/bundle.json"
```

This comparison diagnoses helper issues separately from installed-runtime issues. It is not a substitute for the Work test.

## Stop conditions

Missing local execution, missing helper resources, an inaccessible output, unavailable Node, or a cached wrong version are failed runtime checks. Explain the specific missing capability and fix the packaging/environment before processing real data. Do not switch to a hosted service or request broad account permissions to conceal the failure.

The final rehearsal report should distinguish **package discovery**, **helper execution**, **file correctness**, **account export coverage**, and **AIWP import**. Only mark what was actually exercised.
